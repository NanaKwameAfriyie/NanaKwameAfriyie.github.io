Job Description Portfolio Project

Spotify Platform Analytics Engineering

A portfolio project inspired by Spotify's Analytics Engineer II role, designed to demonstrate SQL-based analytics engineering, dbt-style data modelling, platform metrics, data quality testing, CI/CD, dashboard-ready data products and stakeholder communication.

Back to home GitHub

Role Context

Spotify's Platform Central Data squad supports platform teams by building trusted analytical models, metrics and data products that help teams understand developer productivity, platform health, ML/AI platform adoption and leadership-level operating performance.

Project Scenario

In this scenario, I act as an Analytics Engineer supporting a platform organisation. The goal is to translate platform signals into reliable, well-modelled data assets that help engineering, product and data teams understand whether the platform is helping developers ship faster and safer.

Day-to-Day Work Simulated

  • Define platform health, developer productivity and ML/AI adoption metrics.
  • Design staging, intermediate and mart-level analytics models.
  • Transform raw platform events into trusted dashboard-ready datasets.
  • Add data quality checks for missing values, duplicate keys and invalid statuses.
  • Document model assumptions, metric definitions and known data limitations.
  • Use GitHub-based version control and CI checks to support reliable delivery.
  • Prepare stakeholder-facing summaries for product, engineering and leadership users.

Planned Data Model

  • stg_pull_requests: cleaned pull request activity.
  • stg_deployments: cleaned deployment events.
  • stg_ci_builds: cleaned CI build and test results.
  • stg_incidents: cleaned platform reliability incidents.
  • dim_engineering_team: team and platform ownership metadata.
  • fct_developer_productivity: cycle time, deployment frequency and PR throughput.
  • fct_platform_health: incident counts, recovery time and service reliability.
  • fct_ml_ai_adoption: usage and adoption of ML/AI platform capabilities.

JD Skills Demonstrated

  • SQL and data modelling: building analytical models from raw platform signals.
  • dbt-style transformation: organising models into staging, intermediate and mart layers.
  • Data quality and testability: applying tests for uniqueness, nulls, accepted values and relationships.
  • CI/CD: using GitHub Actions to validate changes before publishing.
  • Metrics design: defining platform health, developer productivity and ML/AI adoption indicators.
  • BI readiness: preparing dashboard-ready tables and stakeholder summaries.
  • Documentation: explaining assumptions, model logic, ownership and success criteria.

Success Criteria

  • The project includes clear business questions and metric definitions.
  • The data model is understandable, reusable and documented.
  • Core models include automated quality checks.
  • CI checks run successfully when changes are pushed to GitHub.
  • Final outputs support dashboarding and decision-making across teams.
